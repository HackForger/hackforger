## 史诗 4: Credits（积分）经济体系

> **史诗假设:** 我们相信，将黑客松奖金、悬赏奖励和资助资金统一到一个可兑换的内部 Credits 经济体系中，将提高平台参与度，因为参与者可以看到在所有活动中积累的切实价值。

---

### 故事 C-003: admin 完成兑换订单

- **概要:** admin 从密钥池分配密钥并完成待处理的订单

#### 用例:
- **作为** 平台 admin
- **我想要** 通过分配激活密钥来完成待处理的兑换订单
- **以便** 用户及时收到奖励

#### 验收标准:

- **场景:** admin 完成订单
- **假设:** RedeemOrder #1 处于 `pending` 状态且密钥池有可用密钥
- **当:** 我用密钥 "COPILOT-KEY-001" 完成订单
- **那么:** 订单状态变为 `fulfilled`，密钥被标记为已使用，用户可以查看其密钥，同时发出 `order_fulfilled(58)` Feed 事件

**旅程参考:** J4 Steps 4.1, 4.2, 4.7

### 故事 C-004: admin 手动充值/扣款

- **概要:** admin 手动调整用户的 Credits 余额

#### 用例:
- **作为** 平台 admin
- **我想要** 对任何用户的账户进行 Credits 充值或扣款并附上原因
- **以便** 处理赞助奖励、错误修正和特殊分配

#### 验收标准:

- **场景:** admin 充值 Credits
- **假设:** `hacker2` 有 400 Credits
- **当:** 我充值 500 Credits，原因为 "社区贡献奖励"
- **那么:** hacker2 的余额变为 900，记录 `admin_deposit` 交易

- **场景:** admin 扣款 Credits
- **假设:** `hacker2` 有 900 Credits
- **当:** 我扣款 50 Credits，原因为 "重复奖励修正"
- **那么:** hacker2 的余额变为 850，记录 `admin_deduct` 交易

**旅程参考:** J4 Steps 4.8, 4.9
