> 涵盖 Hackathon 评委操作

## 史诗 1: Hackathon（黑客松）生命周期

> **史诗假设:** 我们相信，提供一个 Git 原生的黑客松平台——参赛作品以 PR 形式提交、评审直接基于代码进行——将提高提交的完整性并减少组织者的运营负担，因为代码与提交之间的鸿沟被彻底消除。

---

### 故事 H-008: 评分（多标准）

- **概要:** 评委根据加权标准为每件参赛作品评分

#### 用例:
- **作为** hackathon 评委
- **我想要** 按照定义的标准为每件参赛作品评分
- **以便** 参赛作品基于多个质量维度被公正排名

#### 验收标准:

- **场景:** 评委为参赛作品评分
- **假设:** 黑客松处于 `Judging(3)` 状态
- **且假设:** 我被指派为 `judge1`
- **当:** 我为 hacker1 的作品提交评分: Innovation=90, Technical Quality=85, Presentation=80
- **那么:** 评分被记录，加权分数被计算 (90×0.4 + 85×0.35 + 80×0.25 = 85.75)，同时发出 `hackathon_scored(33)` Feed 事件
